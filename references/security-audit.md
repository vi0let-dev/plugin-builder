# 代码审计与隐私保护规范

配套 `SKILL.md` 阶段 8。目标：**产出一份用户能看懂、能复核的审计结论**，不是内部过一遍就宣布安全。

三步流程：自动扫描 → 人工审计 → 修复并复扫。任何一步跳过，都不算完成审计。

---

## 1. 审计范围

必须覆盖项目里**所有**会被交付或发布的文件：

- 源码：`*.js`、`*.mjs`、`*.ts`、`*.jsx`、`*.tsx`
- 配置：`package.json`、`cordis.patch.yml`、`*.json`、`*.yaml`、`*.env*`
- 文档：`README.md`、`docs/**`、注释
- 测试：`test/**`、fixtures、快照
- 资源：图片、SVG（可能内嵌脚本或外链）、示例数据
- 版本控制面：`.gitignore`、`.gitattributes`、已提交的历史（如可查）

不审计 `node_modules`（但审计"是否该有 node_modules"——不该被发布）。

---

## 2. 自动扫描

```powershell
node "<skill 目录>/scripts/audit-scan.mjs" "<项目目录>"
```

输出：按严重度分组的问题清单（file:line + 类别 + 命中片段），以及建议处理方式。有高危项时退出码非 0。

扫描覆盖：

| 类别 | 检测内容 |
|---|---|
| 私钥/证书 | `-----BEGIN ... PRIVATE KEY-----`、证书块 |
| 云厂商凭据 | `AKIA...`、`sk-ant-...`、`sk-...`、`ghp_/gho_/github_pat_`、`xox[baprs]-`、`AIza...` |
| 通用密钥赋值 | `api_key`/`secret`/`token`/`password` 后接长字面量（排除占位符） |
| 授权头 | 硬编码 `Bearer <token>` |
| 本地绝对路径 | `C:\Users\<名>\`、`/home/<名>/`、`/Users/<名>/` |
| 动态执行 | `eval(`、`new Function(`、`innerHTML =` |
| 可疑外联 | `fetch(`/`XMLHttpRequest`/`WebSocket` 到非本机地址 |
| 占位符识别 | 含 `xxx`、`your-`、`<...>`、`example`、`test`、`fake`、`dummy` 的行降级为提示 |

**扫描器只能减少漏检，不能证明安全。** 命中要人判断；未命中不等于没问题（例如把密钥拆成两段拼接、从远端拉取配置）。

## 3. 人工审计清单

### 3.1 凭据

- [ ] 代码、配置、示例、测试、文档里没有真实 Key / Token / 密码 / Cookie
- [ ] 没有把凭据写进日志（包括错误日志里的请求头）
- [ ] 需要凭据时从 `ctx.credentials` 或环境变量读取，**不在插件里存明文**
- [ ] 示例配置用的是明显的占位符，如 `<YOUR_API_KEY>`、`sk-xxxxxxxx`
- [ ] `.gitignore` 覆盖 `.env`、`*.local`、个人配置

### 3.2 隐私数据

- [ ] 明确列出插件读取的每一类数据（会话内容、文件、账号信息、剪贴板）
- [ ] 每类数据都有"为什么需要"的说明
- [ ] 不存在"顺手多读一点"的字段
- [ ] 不把会话内容/文件内容写进日志、缓存文件、遥测
- [ ] 数据离开本机时有显式说明 + 可关闭开关（默认应关闭或最少外发）
- [ ] 持久化位置明确（插件目录 / `$DSH_HOME` / 浏览器存储），并在 README 写清怎么清

### 3.3 网络

- [ ] 请求目标明确、可枚举，没有"发给某个第三方再转发"
- [ ] 只用 HTTPS
- [ ] 有超时、有大小上限、失败不当成成功
- [ ] 响应内容不直接 `innerHTML` 进页面
- [ ] 出网能力可被用户关闭，或至少可被审计

### 3.4 文件系统

- [ ] 读写路径有明确根，不接受任意绝对路径
- [ ] 拼接路径时拒绝 `..`、拒绝逃逸出根目录
- [ ] 写入前检查大小/数量上限
- [ ] 不覆盖用户既有文件（除非用户明确要求且二次确认）
- [ ] 临时文件用系统临时目录，退出时清理

### 3.5 注入与执行

- [ ] 无 `eval`、`new Function`、`setTimeout(string)`
- [ ] 无 `innerHTML` / `outerHTML` / `document.write` 拼接不可信内容
- [ ] 无 shell 命令拼接（用参数数组，不拼字符串）
- [ ] 服务端路由有方法/参数校验与体积上限

### 3.6 权限与能力

- [ ] 调用的 Host service 都是功能必需（`tools`、`fs`、`web` 这类要能说清用途）
- [ ] 没有为了"以后可能用到"而申请的能力
- [ ] 高频/危险操作有确认或限流

### 3.7 依赖

- [ ] 运行时依赖尽量为零
- [ ] 新依赖有明确用途、许可证可分发、无 install 脚本副作用
- [ ] 没有把 devDependency 混进运行时依赖

### 3.8 发布面

- [ ] 无本地绝对路径（`C:\Users\...`）
- [ ] 无临时文件、日志、`.DS_Store`、构建产物
- [ ] 无测试产生的真实数据（真实会话 ID、真实用户目录名）
- [ ] 文档里的命令不含个人 profile 名硬编码（用 `<profile>` 占位）

## 4. 处置方式（按优先级）

| 情况 | 处理 |
|---|---|
| 真实凭据出现在将发布的文件 | **必须删除**，改为占位符或环境变量读取；若已提交过，提示轮换 |
| 凭据出现在 Git 历史 | 改当前文件**不等于**清除历史，明确告知，给出去史建议（`git filter-repo`），但不代为执行 |
| 日志打印敏感内容 | 改成只打事件类型、长度、hash，或脱敏后打印 |
| 示例含真实数据 | 换成构造数据（`user@example.com`、`session-0000...`） |
| 硬编码本地路径 | 改相对路径、环境变量或平台 API |
| 不必要的数据收集 | 删掉，而不是"加个开关默认关闭" |
| 必要但高风险的能力 | 保留 + 明确告知 + 默认关闭 + 写进 README 安全说明 |

原则：**先修，再交付**。发现高危问题却只在报告里写一句"已知风险"，不算完成。

## 5. 脱敏手法

```js
// 日志：只留可诊断信息
logger.warn(`export failed: session=${shortId(id)} bytes=${bytes} code=${error.code}`)

// 展示：中间省略
const mask = (s) => (s.length <= 8 ? '***' : `${s.slice(0, 4)}…${s.slice(-4)}`)

// 示例配置
{ "apiKey": "<YOUR_API_KEY>", "endpoint": "https://api.example.com/v1" }
```

不要用"看起来像真的"的假 Key（`sk-abc123...`）——扫描器和用户都会误判。用 `<YOUR_API_KEY>` 这类明显占位。

## 6. 复扫与结论

修复后**必须再跑一次扫描**，确认高危项清零或已登记原因。

审计报告用 `templates/audit-report-template.md`，至少包含：

1. 审计范围（文件清单 / 版本 / 日期）
2. 检查项（按上面 8 类）
3. 发现的问题（编号、严重度、文件:行）
4. 已修复（怎么修的）
5. 未解决（为什么不修、影响、建议）
6. 隐私数据处理结果（读了什么、发到哪、怎么清）
7. 是否发现真实凭据（有/无，若有说明处置与轮换建议）
8. 是否可以安全交付（明确结论）
9. 复扫结果

结论只有三种：**可安全交付** / **修复后可交付**（列出待修项）/ **不建议交付**（说明原因）。不允许含糊。

---

## 7. 报告中如何表述风险

不要写"可能有安全问题"这种无法行动的话。写：

> `index.js:88` 把完整会话内容写进日志（`logger.info(text)`）。已改为只记录会话 ID 与字符数。若用户曾在旧版本运行过，本地日志文件中可能留有历史内容，建议清理 `$DSH_HOME/logs/`。

即：**位置 + 原问题 + 已做的处理 + 用户需要自己做的事**。
